# 测试实践

被测对象即本项目自身（FastAPI + PostgreSQL/SQLite）。分五层，全部可本地复现。

## 分层与规模

| 层级 | 位置 | 手段 | 规模 | 结果 |
|---|---|---|---|---|
| 单元 / 集成 | `tests/` | `TestClient` + `dependency_overrides` 隔离测试库 | 28 项 | 全通过，覆盖率 87% |
| 接口自动化 | `automation/` | `requests` 直连运行中的服务 | 34 项 | 全通过 |
| 安全检查 | `security/` | 标准库直连，零第三方依赖 | 16 项 | 13 通过 / 3 缺口 |
| 数据一致性 | `tests/test_data_consistency.py` | 接口输出 vs 库表逐字段比对 + 篡改反证 | 2 项 | 全通过 |
| 性能 | `perf/` | ApacheBench 50/100/200 并发 | 3 组 | TPS 1194 / 1170 / 超时 |

## 单元与集成（tests/）

每个用例前重建表结构，用例之间互不污染；测试库是独立 SQLite 文件，
用例结束自动删除，不触碰开发库。

覆盖：数据源 CRUD 与 404 边界、表与字段创建与列表、三类规则创建与执行（通过/不通过两种结果）、
校验历史留存、血线上游溯源与下游影响、非法规则类型、自引用血缘、健康与就绪探针、
请求 ID 透传、统一错误体形状、422 字段级错误。

```bash
make test
make cov      # 覆盖率明细
```

## 接口自动化（automation/）

真实 HTTP 黑盒，跑在已经启动的服务上，验证的是「装配后」的行为，而不是进程内对象。

```bash
cd automation && ./run.sh      # 依赖齐全时生成 report.html
```

## 安全检查（security/）

四类 16 项：注入 4、畸形输入 5、信息泄露 4、鉴权 3。
结论：13 通过，3 项为设计缺口（无鉴权、缺安全响应头、无限流），0 项可被利用。

已修复缺陷：

| 编号 | 现象 | 根因 | 修复 | 回归 |
|---|---|---|---|---|
| S02 | `GET /datasources/9999999999999999999999` 返回 500 | int 溢出 PostgreSQL int4，驱动抛 `DataError` 且无处理器 | 统一异常处理，数据库异常转 4xx，不回显驱动细节 | 500 → 422，正常请求仍 200 |

## 数据一致性

把接口返回与库表记录分别取出，按主键排序后逐字段比对，不一致时指出行号、字段名与两侧取值；
再构造篡改场景，证明比对具备判别力（篡改后必须断言失败）。

> 实现不依赖 pandas：本机虚拟化环境 CPU 不支持科学计算库所需指令集，
> 改用原生查询与排序比对，断言信息更精确。

## 性能与容量

连接池 `pool_size=20`、`max_overflow=40`（上限 60）时的实测：

| 并发 | 与上限关系 | TPS | P95 | 表现 |
|---|---|---|---|---|
| 50 | 未超限 | 1194.31 | 55 ms | 零失败 |
| 100 | 超限 40 | 1169.57 | 100 ms | 延迟抬升，仍可用 |
| 200 | 超限 140 | — | — | 排队超 `pool_timeout` 10s，超时 |

当前配置已调整为 `pool_size=10 / max_overflow=20`（上限 30），压测结论需重跑复核。
瓶颈在连接数而非 CPU：每个请求占一条连接，超出部分排队。
扩容方向为扩大连接池、引入连接复用、多实例或前置 PgBouncer。

## CI

`.github/workflows/ci.yml` 三个 job：

1. `lint`：ruff check + ruff format --check
2. `test`：pytest + 覆盖率，Python 3.12 矩阵
3. `docker`：构建镜像，验证容器可构建

本地推之前先跑 `make lint test`，避免烧 CI 配额。
